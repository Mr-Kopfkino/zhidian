# 致电 · ZHIDIAN

可以由你定义的 Windows 桌面电子朋友。C# 核心 + WPF/XAML 原生界面，聊天界面不依赖浏览器或 Node；内置语音使用随应用携带的独立 Python 推理环境，无需系统安装。

## 下载与运行

当前版本 **2.2.0**，支持 **Windows 10/11 x64**。请从本仓库的 **Releases** 页面下载软件；GitHub 自动提供的 `Source code (zip)` / `Source code (tar.gz)` 是源码，需要自行构建。

完整便携包附带 .NET 桌面运行时、独立 Python 环境和 GPT-SoVITS 推理引擎，无需安装 .NET、Python 或 CUDA Toolkit。完整包按分卷提供，请将以下文件下载到同一个有写入权限的目录：

- `Zhidian-v2.2.0-win-x64.zip.001`、`.002`、`.003`、`.004`（四卷全部必需）。
- `Extract-Zhidian.cmd`、`Extract-Zhidian.ps1` 和 `release-manifest.json`。

双击 **`Extract-Zhidian.cmd`**，脚本会校验下载文件、还原 ZIP 并解压。完成后进入解压出的程序目录，双击 **`Zhidian.exe`**。请保留整个程序目录，不要只复制 EXE，也不要直接从压缩包内启动。若已取得完整的 `Zhidian-v2.2.0-win-x64.zip`，也可完整解压后直接运行。

初次运行会创建空白的本地数据。发布包不包含用户聊天、密钥、私人角色权重、参考音频或运行缓存。**聊天需要配置自己的兼容模型服务；内置语音需要自行提供有权使用的角色权重和参考音频。** 下载软件不代表已经附带聊天大模型或某个角色的声音。

2.0.2 将应用更名为“致电”，启动文件为 `Zhidian.exe`。源码中的 `Qiban` 命名空间、开发构建输出中的 `Laidian-*` 名称和引擎内部标记为兼容历史版本而保留。

**设置 → 外观 → 界面风格** 可切换“标准”和“Windows XP”，选择后立即生效并自动保存，重启后沿用。XP 风格采用经典蓝色标题栏和面板、白色标签及立体控件，覆盖侧栏、聊天气泡及设置；不改变系统主题，不影响角色、聊天背景、语音配置和长期记忆。样式来源与许可见 [主题说明](docs/THEME.md)。支持平台仍为 Windows 10/11，不支持在 Windows XP 系统上运行。

1.5 版使用与应用配色一致的窗口边框及标题栏。保留边缘缩放、标题栏拖动/双击、右键系统菜单、最小化、最大化/还原和关闭操作；关闭仍经过原有保存流程。系统支持时使用原生圆角与阴影。

从旧版升级：关闭旧版，将原程序目录中的完整 `data` 文件夹复制到新版 `Zhidian.exe` 所在目录后再启动。新版输出使用独立目录，不会删除旧发布目录或自动搬移用户数据。保留旧目录直至确认人物、聊天和记忆完整；不要把两个已有用户数据的 `data` 文件夹直接合并。同一 Windows 用户下已保存的密钥仍可使用。

源码目录提供经过校验的迁移脚本：`scripts/upgrade-data.ps1 -SourceProgram <旧程序目录> -DestinationProgram <新程序目录>`。它要求两版均已关闭、新目录尚无 `data`，逐文件校验后一次性提交，保留原数据。升级后使用新版继续记录，避免在两个独立目录间交替编辑。

发布文件夹也附带同一个 `Upgrade-Data.ps1`；可在 PowerShell 中使用 `powershell -NoProfile -ExecutionPolicy Bypass -File .\Upgrade-Data.ps1 -SourceProgram "旧目录" -DestinationProgram "新目录"` 迁移。

初次运行不预设任何付费服务或私人密钥，也不会自动下载模型。进入 **设置 → 对话模型**，填写兼容 Chat Completions 的基础地址、模型 ID 和可选密钥，保存并测试连接。API 密钥使用当前 Windows 账户的 DPAPI 加密，换账户/电脑需重新填写；输入框留空保留原密钥，输入 `-` 清除。

- LM Studio：启动本地服务，常见地址 `http://127.0.0.1:1234/v1`，模型名称以本地服务为准。
- Ollama 的兼容接口：常见地址 `http://127.0.0.1:11434/v1`，模型须预先安装。
- 远程服务：使用服务商提供的 `https://…/v1` 或完整 `https://…/chat/completions` 地址。
- 连接测试读取 `/models`，不产生聊天推理。少数服务未实现此路由，需用实际聊天确认。
- 原生流式聊天、停止生成、失败后重试；Enter 发送，Shift+Enter 换行；右键消息可复制、加入记忆或朗读。
- 2.0.1 修复多行输入框吞掉回车发送事件的问题，保留输入法确认候选词与 Shift+Enter 换行，并抑制长按回车重复提交。
- 网络请求只发送到你配置的服务。远程接口必须 HTTPS，本机接口可 HTTP；禁用自动重定向，避免凭据随跳转泄漏。

## 人物与形象

默认角色为五河琴里，已根据动画与官方游戏资料配置背景及表达方式，默认偏黑缎带的司令官性格。资料来源与改编范围见 [默认角色说明](docs/KOTORI.md)。人物设定仍可自由编辑；旧默认角色会安全升级，已自定义角色不覆盖。

在设置中填写姓名、个性签名、人物设定和初次问候，支持任意文字设定与语言。可以创建多位朋友，每位朋友的对话、记忆、头像、立绘、背景、日语模式和语音配置相互独立。文字对话模型连接为全局设置。

头像和静态立绘支持 PNG/JPEG/BMP/GIF（GIF 显示静态帧），建议透明 PNG 立绘；单文件最大 20 MB。素材会复制到程序的 `data/assets`，不会依赖导入原文件的位置。此版本不包含 Live2D/3D 动画驱动。

1.4 版新增 **设置 → 角色 → 聊天背景**：为当前角色选择本地图片，居中等比铺满消息区域。背景固定在消息下方，随窗口尺寸裁切，并适度淡化以保持文字清晰；选择后立即保存，点击“移除背景”恢复默认底色。支持 PNG/JPEG/BMP/GIF 静态图片，最大 20 MB，图片解码最长边限制为 1920 像素。不同角色独立保存背景；原图移动或删除后仍可使用，清理缓存不影响背景。更换或移除后，无角色或有效恢复快照引用的旧素材自动回收。角色 JSON 导出不包含背景图片，完整迁移应复制 `data`。

角色导出 JSON 包含人物设定、聊天、记忆与非敏感的声音预设，不包含密钥或图片文件。声音预设仅保留接口类型、模型、音色、语言及参考文本；服务连接、自定义请求模板和本机文件路径需重新填写，导入后语音默认关闭。导入时创建新角色，不覆盖原朋友。完整迁移可在关闭应用后复制整个文件夹，或仅备份 `data`；新 Windows 账户需重新填密钥。

## 主动聊天

1.3 版新增 **设置 → 主动聊天**。待机与电脑活动两种触发默认开启，可分别关闭；默认连续发出 3 条未获回复的主动消息后暂停，收到用户消息后恢复。

1.8 版修复角色节奏分析未完成时两种触发都被阻塞的问题。分析改为后台执行；等待或失败期间使用临时节奏（待机随机 5～15 分钟、活动概率 25%、活动冷却 5 分钟），仍由已配置的大模型结合人物设定和上下文撰写消息。分析成功后采用角色专属节奏，保留已过等待时间及未回复计数。辅助分析失败后间隔 2 分钟再尝试；实际聊天优先于分析。“触发状态”显示当前倒计时、临时/角色节奏、排队、会话暂停、发送失败重试或未回复上限。

- 人物设定首次使用或修改后，由已配置的大模型分析等待区间、活动触发概率与冷却时间，结果随角色保存。每次待机计时重新随机；怕寂寞与寡言角色使用不同节奏，实际数值可在设置查看。分析失败会间隔重试，并明确显示临时节奏，不用固定台词替代消息内容。分析接口兼容代码围栏、完整思考标签后的最终 JSON 和服务强制返回的 SSE；仍拒绝截断、缺字段或多组歧义结果。
- 1.9 版将前台采样缩短为每 2 秒一次，同一应用连续稳定 2 秒后按角色概率判断。概率未命中会在 15～120 秒后重新评估（角色活动冷却的 1/20），不再直接等待完整发送冷却；例如活动概率 28%、冷却 12 分钟的角色，未命中后 36 秒可再次评估，成功发送活动消息后仍冷却 12 分钟。普通用户发言或短暂切换前台不会绕过同一应用的评估间隔；待机主动消息只占用全局 30 秒间隔，不再推迟完整活动冷却。
- 浏览器、游戏、播放器和其他应用均可触发，无需先等待聊天空闲。支持识别由 Windows 窗口宿主承载的应用；“触发状态”显示前台应用及下一次评估倒计时。返回致电后短暂保留最近识别信息供检查，已离开的应用不会因这条显示信息继续触发。
- 主动消息由外接对话模型结合人物设定、近期聊天、已确认记忆及本次活动生成。正在生成普通回复时最多暂存一次活动触发，回复结束后自然转入新话题；用户发送消息可中止主动生成并优先发送。草稿会保留。
- 仅提供前台进程名及类别，不读取窗口标题、网页地址、屏幕或文件内容。分类基于程序名，未知应用仍可参与；启动器、桌面壳和后台常驻程序不会被当作正在使用的游戏。瞬时观察不自动写入长期记忆，生成的聊天按普通聊天持久保存。
- 仅当前选中的角色主动发言。锁屏时暂停；休眠恢复后重新计时，不补发积压消息。关闭程序后不监测、不触发。请求失败采用递增退避，连续未回复上限在重启与角色切换后仍然有效。

主动聊天与首次角色节奏分析会调用你配置的模型服务，计费与普通对话遵循相同服务规则。

## 长期记忆

2.2 版默认开启 **设置 → 对话模型 → 自动整理长期记忆 / 自动生成对话摘要**。使用当前配置的对话模型，在回复结束后短暂空闲时后台整理，无需说“记住”。两项功能可以分别关闭；关闭后保留已有记忆与摘要。整理会额外调用同一模型服务，使用其现有计费规则。

模型判断哪些用户经历、稳定偏好、事实与明确约定值得记住，并引用用户原话。来源和原文片段经过本地校验；置信度至少 0.85 且无已报告冲突的条目自动生效，至少 0.5 但低于 0.85，或存在冲突的内容待确认，低置信内容忽略。模型不能覆盖已有记忆，角色猜测和电脑进程观察不能作为用户事实来源。自动判断可能出错，可在记忆页查看来源、编辑或归档。

摘要保留用户陈述与角色建议的区别，最多 12 条、2400 字符，供普通和主动聊天继续使用。首次启用从最近 24 条对话开始；之后按已保存进度分批整理新消息，避免反复请求，连续聊天造成的积压在空闲后按顺序处理。中文、日语及其他语言的消息都交由模型理解，证据保留原文。角色设定及其他角色的数据不会发送给整理请求。

左侧 **记忆** 显示整理状态、自动记忆、待确认项与可展开的对话摘要，可点击“立即整理”处理待整理对话或重试失败请求。失败间隔 2 分钟再尝试，进度不提前推进；新聊天会取消后台整理，优先回复用户。删除/归档记忆会屏蔽旧来源再提炼，清除摘要也不会立即从同一批历史重建；用户之后的新消息仍可正常学习。清空聊天保留长期记忆，并清除摘要与整理进度。

聊天记录、结构化长期记忆及摘要按角色分别保存。记忆包含类别、来源消息、写入方式、创建/更新时间、最近引用时间、生效状态、置顶标记和可选到期时间。

1. 自动整理开启时，普通表达和“记住”请求一起交由模型分析。关闭自动整理后，可使用“手动模式下提取‘记住’指令”生成**待确认**条目；也可以右键用户消息，或手动新增。
2. 在记忆页核对来源、修改内容，待确认项需点击确认。**待确认、归档、过期条目都不会参与长期记忆检索。**自动保存项标为“自动记忆”。
3. 已生效条目按中文双字/拉丁词匹配、时效和置信度排序，置顶优先；字符预算限制长期记忆占用，最多引用 24 条。摘要使用独立的有限预算。
4. 可编辑、搜索、归档、恢复、设置到期或永久删除。删除时可同时删去来源消息及其紧随的回复；仅删除记忆时，聊天原文仍会保留在短期上下文中。导出文件与人为保存的副本需自行处理。
5. 删除操作同步刷新恢复备份，避免下一次恢复把删除的记忆重新带回。`state.damaged-*.json` 损坏文件为人工恢复材料，不会自动重新导入，也不会随删除操作擦除；如需彻底移除相关内容，请同时处理这些文件与导出副本。

1.1 版对持久化作了加固：首次保存就生成两份**最新**快照，每份含修订号与 SHA-256 完整性校验。写入通过临时文件、落盘刷新和原子替换完成。备份先完成即为提交点；另一份暂时无法写入时明确提示，重启按最高有效修订恢复，避免删除中断后旧记录重新出现。

读取时严格检查必需字段；空对象、缺失记忆列表、校验失败不会被默认为空数据。两份都无法恢复时停止写入并保留原文件。跨实例写入受文件锁和修订校验保护，陈旧状态不能覆盖较新的记忆。界面保存失败保留编辑草稿，解除占用后可重试。

旧版完整数据可直接读取，首次保存自动升级；旧密钥加密方式不变。完整性校验用于发现意外损坏，不是防篡改认证；不要手工编辑快照文件。两份快照在同一磁盘，仍建议定期导出到独立位置。

长期条目的检索仍为轻量词法匹配，未捆绑向量模型；新功能由对话模型提炼事实、维护摘要，并以原文依据和已有状态约束写入。自动整理和摘要与原有原子存储、双副本恢复及缓存隔离共用同一数据机制，不生成额外的聊天日志或临时文本文件。

## 自定义语音模型

2.0 版完整内置精简的 GPT-SoVITS 推理环境，无需另开服务。仅包含合成所需代码、运行库及基础资源，不包含训练、WebUI、ASR 或分离工具；也保留外接 TTS。详见 [内置语音说明](docs/VOICE_ENGINE.md)。

1.6 版修正为**每个角色独立配置声音**。先在左侧选择角色，再进入 **设置 → 角色声音**，分别设置服务地址、密钥、模型、音色、参考音频/文本、权重、请求模板及自动朗读开关。切换角色即切换对应设置，取消上一角色的语音输出并停止播放；已发出的权重加载会等待服务确认后再切换，避免交错。新角色采用未启用语音的独立默认配置。升级时，旧全局声音配置复制为现有各角色的独立副本，之后修改互不影响。

- **GPT-SoVITS 内置**：为当前角色选择 GPT `.ckpt`、SoVITS `.pth` 和参考音频，填写参考文本及语言，加载或试听。直接使用应用内推理环境；每个角色独立配置，取消、切换、退出及闲置卸载均清理专属缓存。默认使用可用 NVIDIA GPU，无 CUDA 时使用 CPU。
- **GPT-SoVITS 外接**：启动其 `api_v2.py` 服务；填写完整 `/tts` 地址（常见 `http://127.0.0.1:9880/tts`）、语言、参考音频、参考文本。不同角色共用本机服务时，为每个角色同时填写 GPT `.ckpt` 与 SoVITS `.pth` 权重路径；每次合成前自动加载当前角色的完整权重组合，挂载与合成依次执行，避免相互覆盖。也可点击“挂载模型”检查。路径必须可被服务进程访问，挂载限定本机；只填写一项权重会被拒绝。两项均留空时使用服务已经加载的模型，此时不同模型应使用不同服务地址。任一步挂载失败都会停止本次合成，不继续使用旧声音。其他应用直接操作同一服务不受致电的串行控制。
- **OpenAI-compatible**：填写完整 `/audio/speech` 地址、模型 ID、音色和可选密钥，请求 WAV 格式。
- **Custom JSON**：填写完整 POST 地址和 JSON 模板，在任意字符串字段中使用 `{{text}}`，应用会按 JSON 字符串安全替换。接口必须直接返回 WAV 或 MP3 二进制；不支持返回 URL/JSON/Base64 的接口。

响应最大 32 MB，支持超时、取消和清理不完整下载。可以试听、自动朗读回复，或右键某条回复单独朗读。播放结束会释放播放器并删除生成文件。

外部语音/模型服务由用户独立启动，因此其自身的缓存与模型下载目录**不受本应用控制**。应将服务的 TEMP/TMP、HF_HOME、TORCH_HOME 等目录也设到希望的磁盘；参考音频与模型权重属于用户资产，不作为垃圾删除，即使取消角色的声音配置也会保留。素材自动回收仅针对应用导入后不再使用的图片副本。

## 日语聊天模式

1.7 版新增 **设置 → 角色声音 → 日语聊天模式**。为当前角色勾选后，在“聊天显示语言”中选择简体中文、繁體中文、日本語、English、한국어，也可直接输入其他语言名称。用户输入语言不限，应用不修改用户消息；显示语言作用于后续回复，已有记录保持原样。要自动发声，还需启用当前角色的语音及“回复后自动朗读”。

- 普通回复与主动消息都先由已配置的对话模型按人物设定生成日语原文，再由同一模型翻译成所选显示语言；选择日语显示时省去翻译请求。翻译可能增加等待时间与模型调用费用。
- 语音始终取日语原文，界面译文不传给语音合成。原文与显示译文一并保存、备份与导出；日语模式下的上下文优先使用日语原文。长期记忆仍保留用户消息及其原始来源，不把模型译文自动当作事实。
- 翻译失败时保留已生成的日语原文，点击重试只补做翻译，不重新生成回复。失败或中止的消息不自动朗读。模式开启后朗读旧的非日语消息，会先请求模型转换为日语；无法准备日语时停止本次朗读。
- GPT-SoVITS 合成参数固定 `text_lang=ja`；“常规 / 参考语言”仍用于参考音频的 `prompt_lang`，不会因为日语模式覆盖参考音频的实际语言。兼容语音接口收到日语文本；所接声模必须支持日语，应用不能使仅支持其他语言的模型具备日语发音能力。
- 自定义 JSON 接口在日语模式下必须提供 `{{language}}` 占位符，例如 `{"text":"{{text}}","language":"{{language}}","format":"wav"}`；它会被替换为 `ja`，字段名须符合外部服务协议。正常模式则使用角色保存的语言值。
- 日语输出逐句、逐行检查假名并拦截外语字母。2.0.3 对含英文软件名、纯汉字短句等未通过校验的非空回复，先由已配置模型忠实转换为可朗读日语一次，再重新校验；不重新生成话题，成功后才翻译显示文本或合成语音。额外转换仅在校验失败时发生，可能增加等待与模型费用。仍失败则停止合成并按原策略退避，不循环转换、不把失败主动消息计入未回复次数，也不回退朗读其他语言。字符检查不能替代语言理解；日语自然度、翻译准确度和发音效果取决于所接模型及语音服务。

## 数据与缓存

运行目录结构：

```text
Zhidian.exe / *.dll / 运行时文件 程序文件
data/state.json                人物、设置、消息、长期记忆（原子写入）
data/state.backup.json         第二份最新、可校验快照
data/.store.lock               读写互斥锁（空文件，非缓存）
data/assets/                   导入的头像与立绘
cache/                         可删除的合成音频、临时文件和过程缓存
```

- 启动检查目录可写性；拒绝数据目录上的符号链接/目录联接，避免写到程序外部。
- 对本进程重定向 TEMP/TMP 等环境变量；不会修改 Windows 全局环境。
- 每 3 分钟按年龄和容量清理缓存，默认 24 小时/128 MB；语音活动期间避开清理。内置推理独占会话目录，取消、退出及约一分钟闲置卸载时清理；音频播放结束立即删除，异常退出残留在下次启动回收。
- 正常退出清空缓存。崩溃/断电时无法执行退出代码；下次启动取得独占锁后清空遗留缓存，数据从最高修订的有效快照恢复。
- 手动“清理缓存”不删除聊天、角色、记忆或用户模型。无引用头像/立绘在成功保存后回收，同时保护恢复备份所需素材。
- 存储不自动丢弃聊天：单个状态文件最大 128 MB，超过后提示先导出/清空。界面仅绘制最近 200 条消息，完整聊天可导出。
- **无法保证任何情况下零 C 盘写入**：Windows 的预取、事件日志、虚拟内存、GPU/音频驱动和系统运行库可能产生系统级写入，进程无法全面约束。应用自身的数据和缓存以程序目录为边界。

采用文件夹发布，避免自解压单文件应用把原生运行库提取到用户临时目录。运行库文件是程序依赖，不是缓存。[Microsoft 发布说明](https://learn.microsoft.com/en-us/dotnet/core/deploying/single-file/)
